# 05 · Identidad y publicación

## Objetivo

Eliminar contradicciones heredadas y comprobar que las funciones públicas y el proceso de publicación corresponden a la web actual.

## A. Identidad y textos

- [x] Sustituir las referencias de presentación a `TopeRC.es` por la marca TopeRC o el dominio actual, `toperc.com`, según el contexto.
- [x] Conservar el correo y los nombres de usuario de redes que incluyen `.es` mientras sigan siendo las cuentas reales; no cambiar sus destinos por semejanza con el dominio nuevo.
- [ ] Reescribir «Sobre nosotros» con información aportada por el equipo y recursos que existen de verdad.
- [ ] Revisar afirmaciones genéricas como «el sitio número uno» y promesas de actualizaciones o servicios que no estén documentados.
- [ ] Sustituir invitaciones a comentar por un canal activo, salvo que decidamos implementar un sistema de comentarios.
- [ ] Inventariar las referencias a servicios antiguos en la configuración y en los textos informativos.

## B. Contacto y servicios externos

- [ ] Confirmar qué correo, canal de Telegram y perfiles sociales se mantienen activos.

- [ ] Acordar destinatario y texto de prueba antes de realizar un envío real expresamente autorizado; comprobar su recepción.

- [ ] Revisar con el titular los textos informativos para que describan los servicios usados. Tratar cualquier revisión jurídica sustantiva como un trabajo específico, con los datos y fuentes necesarios.

## C. Presentación en buscadores y redes

- [ ] Revisar títulos, descripciones, URLs canónicas y metadatos para compartir páginas en redes.
- [ ] Evitar descripciones de producto o datos estructurados basados en características que no estén verificadas.
- [ ] Comprobar que sitemap y feed contienen las páginas esperadas al añadir la colección de modelos.
- [ ] Revisar los enlaces de redes y vídeos heredados, incluidos los distintos formatos de URL del canal de YouTube.

## D. Publicación mantenible

- [ ] Llevar la comprobación de enlaces internos y de etiquetas al flujo de validación del repositorio.
- [ ] Revisar las advertencias observadas en el último despliegue sobre las versiones de GitHub Actions; actualizar con una compilación comprobada.
- [ ] Revisar dependencias y plugins que ya no se utilizan y documentar el entorno de desarrollo admitido.
- [ ] Documentar cómo publicar una iteración y cómo recuperar la versión anterior con Git y GitHub Pages.

## Entrega y criterio de cierre

Las referencias de marca son coherentes, el visitante encuentra canales activos y la recepción del formulario está comprobada mediante una prueba acordada. Las páginas se comparten con metadatos correctos, y la publicación tiene sus comprobaciones y un procedimiento documentado de recuperación.

## Dependencias

El equipo confirma su presentación y los canales que usa. Las fichas y metadatos de los bloques 02–04 deben estar definidos para cerrar sitemap y presentación social. El envío real del formulario no se considera comprobado por el simple hecho de que la página cargue o el campo tenga validación.
